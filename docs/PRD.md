# 수원시립미술관 PC·모바일 웹 개선 PRD

> 본 문서는 제공된 현황 분석, 문제점 구조화, 핵심 가설, 사용자 여정, 와이어프레임 반영 사항, Peer UT 결과만을 근거로 작성했습니다. 근거가 부족한 항목은 **"추가 확인 필요"** 로 표시했습니다.

## 1. 문서 개요 (Document Overview)

### 1.1 프로젝트 목적
수원시립미술관 PC 데스크탑 및 모바일 웹의 접근성, 직관성, 공공언어 명확성을 개선하여 관람객이 **현재 열리고 있는 전시를 확인하고, 분관별로 전시를 필터링하며, 오시는 길과 휴관일을 바탕으로 방문 계획을 세울 수 있도록** 한다.

### 1.2 문제 정의
현황 분석에서 확인된 9건의 문제는 두 가지로 분류된다.
- **법적 접근성 결함**: KWCAG 2.2 미준수
- **오프라인 방문 실패를 유발하는 UX 장벽**: 잘못된 관 방문, 휴관일 방문 등

### 1.3 목표
| 구분 | 내용 |
| --- | --- |
| 접근성 | 포스터 속 글자의 텍스트 전환, 대체 텍스트 제공, 명도 대비 4.5:1 이상 확보, 캐러셀 정지 기능 제공 |
| 과업 효율 | 관별(행궁본관/광교관/만석전시관/북수원전시관) 필터, 상태 배지, 종료 임박순 정렬, 운영시간·휴관일·오시는 길 직결 제공 |
| 검색 사용성 | 검색창 레이블 연결, 검색어 유지, 검색 결과 건수 안내 |

### 1.4 우선순위
| 순위 | 테마 | 사유 |
| --- | --- | --- |
| P1 (Critical) | 정보 인식성 및 시각 접근성 강화 | 스크린리더·저시력 사용자의 이용 차단 방지, 법적 필수 준수 항목(KWCAG 2.2) |
| P2 (High) | 전시 탐색 및 과업 수행 효율성 제고 | 오방문 및 헛걸음을 직접 방지하는 핵심 과업 품질 항목 |
| (미지정) | 검색 사용성 및 인터랙션 피드백 강화 | 우선순위 등급은 자료에 없음 → **추가 확인 필요** |

### 1.5 핵심 가설
> 수원시립미술관의 특정 관 전시를 확인하려는 관람객을 위해, 전시 카드의 포스터 속 글자를 텍스트 마크업으로 전환하고 관별 필터와 '전시 중/종료 임박' 상태 배지를 제공하면, 오방문 위험을 없애고 빠르게 방문 계획을 세울 수 있을 것이며, 과업 소요 시간 25초 이내(50% 감소), 오류 0회, 과업 성공률 100%로 확인할 수 있다.

### 1.6 벤치마킹
- **대상**: 국립현대미술관(서울/과천/덕수궁/청주), 범정부 UI/UX 디자인시스템(KRDS)
- **적용 요소**
  1. 다분관 통합 목록에서 특정 관만 분리해 보는 드롭다운 필터 및 텍스트 기반 상태 배지
  2. 범정부 표준 접근성 마크업(공식 배너, 건너뛰기 링크, 모바일 44px 이상 터치 영역, 푸터 개인정보처리방침 표준 레이아웃)

## 5. UI/UX 및 정책 요구사항 (UI/UX & Policy Requirements)

### 5.1 준수 기준
| 기준 | 적용 내용 |
| --- | --- |
| KWCAG 2.2 | 색에 무관한 콘텐츠 인식, 적절한 대체 텍스트, 레이블 제공, 텍스트 명도 대비 4.5:1 이상, 캐러셀 정지 기능, 적절한 링크 텍스트 |
| KRDS | 이미지 텍스트 지양, 검색 레이블, 검색 결과 수 표시 및 검색어 유지, 필터·정렬 제공, 서비스 정보 확인 직결, 상태 정보 제공, 고대비 가이드 |
| Nielsen 휴리스틱 | 시스템 상태 가시성, 유연성과 효율성, 에러 예방, 일관성과 표준 |

### 5.2 공공언어 가이드라인
- 상태 표현은 "전시 중 / 종료 임박 / 전시 예정", 프로그램은 "접수 중 / 마감"으로 통일한다.
- 링크 텍스트는 목적지가 드러나도록 한다("자세히 보기", "전시 상세 보기", "오시는 길 & 관람시간").
- 4개 관의 명칭은 "행궁본관, 광교관, 만석전시관, 북수원전시관"으로 일관되게 표기한다. (현황표의 "행궁/광교/만석/북수원" 약칭과 혼용 여부는 **추가 확인 필요**)
- 상태 배지 표기는 와이어프레임에서 이모지(🔴🟢🔵)를 함께 사용했으나, 실제 구현 시 색상·아이콘 표현은 **세부 스펙은 다음 단계에서 확정 예정**이며, 어떤 경우에도 텍스트를 병기한다.

### 5.3 시각적 우선순위
1. 전시 상태 배지와 제목, 개최 관, 기간을 카드에서 우선 인지하도록 배치한다.
2. 방문 판단에 필요한 정보(휴관일, 오시는 길)는 카드 하단에서 즉시 접근 가능하도록 한다.
3. 휴관일 안내는 고대비로 강조한다.

### 5.4 레이아웃 규칙
- **PC**: 목록 상단에 관 선택 드롭다운과 정렬 컨트롤 배치. 카드 우측/하단에 텍스트 정보 표기
- **모바일**: 1열 카드 스택, 관 선택 필터 스티키 고정, 터치 영역 44px × 44px 이상
- **전체**: 최상단 건너뛰기 링크와 공식 배너, 푸터 개인정보처리방침 표준 레이아웃
- 색상 코드, 폰트·간격 등 세부 수치: **세부 스펙은 다음 단계에서 확정 예정**

## 6. 반응형 (Responsive)

### 1. 브레이크포인트

| 구분 | 범위 | 기준 디자인 |
|---|---|---|
| 모바일 | ~767px | Figma 모바일 시안 |
| 데스크탑 | 768px~ | Figma 데스크탑 시안 (1440px 기준) |

- 1440px은 데스크탑 디자인의 기준 너비이며, 768px~1439px 구간은 데스크탑 레이아웃을 유동적으로 축소해 대응한다. [확인 필요]
- 1440px 초과 화면에서는 콘텐츠 영역을 최대 너비로 제한하고 가운데 정렬한다. 배경은 화면 전체로 확장한다. [확인 필요]
- 최소 지원 너비는 360px이며, 그보다 좁은 화면에서도 가로 스크롤이 생기지 않아야 한다. [확인 필요]

### 2. 작성 원칙

- 모바일 우선으로 작성한다. 기본 스타일은 모바일 기준으로 작성하고, 데스크탑 스타일은 `min-width` 미디어쿼리로 덮어쓴다.
- `max-width` 미디어쿼리는 사용하지 않는다.

### 3. 단위 규칙

- 레이아웃 너비와 간격은 `%`와 `rem`을 사용한다.
- 루트 폰트 크기는 브라우저 기본값(16px)을 유지한다. (1rem = 16px)
- 고정 px 너비는 지양한다.
- `em` 단위는 사용하지 않는다.
- 다음 경우에만 px 사용을 허용한다.
  - border, 구분선 (예: 1px)
  - box-shadow
  - 미디어쿼리 브레이크포인트 값
  - 콘텐츠 영역 최대 너비(max-width)
- 모바일 화면 높이가 필요한 경우 `vh` 대신 `dvh`를 사용한다.

### 4. 공통 처리

- 이미지와 영상은 부모 너비를 넘지 않도록 하고(`max-width: 100%`), 원본 비율을 유지한다.
- 터치 영역은 최소 2.75rem(44px) × 2.75rem을 확보한다.
- hover 효과는 `@media (hover: hover)` 안에서만 적용한다.
- 모바일 네비게이션 형태(햄버거 메뉴 등)는 Figma 시안을 따른다.

### 5. 디자인 전달

- 반응형 상세 디자인은 구현 단계에서 사이즈별 Figma 링크로 전달한다.
- PRD와 Figma 시안이 다를 경우 Figma 시안을 우선한다.
